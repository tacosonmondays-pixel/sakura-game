## 5. How to run the pipeline (what worked)

- **One builder per piece.** Effort is high or xhigh for art and models. Cloud sessions can't take an effort setting, so model work ran as local `Agent` calls with `effort` and worktree isolation; they need Blender 5.2.3 (in the coordinator container).
- **An independent reviewer per piece.** Re-use the same reviewer session for delta rounds; it keeps its context.
- **Render-and-look loop for any model or VFX.**
  - `tools/tripo/clip_strips.py`: 10-frame strips from the battle camera.
  - Playwright captures at 390x844 and 1280x720, day and night, high and medium (LOD).
  - Make a board JPEG ≤300 KB and look at it yourself before reporting.
- **Release assembly session.**
  - Make a `release/v0.1.N` branch off main and `--no-ff` merge the reviewed SHAs.
  - Write one combined patch note, dated by the US **Central** deploy day. **DST ended Nov 1: Central is now UTC−6.**
  - Gates:
    - npm test;
    - simId;
    - noNerfGate `--support none` vs live;
    - lrBar when the sim changes;
    - e2e: smoke, engines, multiplayer, model-quality, weapon-muzzles, path-looks, staff-models, plus feature-specific ones;
    - build without dev panels;
    - blob and refs checks.
- **Go/no-go session.** Rebuild the merge independently, pair a cross-version co-op game, round-trip a save, do a visual pass, run the tests.
- **Ship.**
  - Check main is an ancestor of the release, then `git push origin <sha>:main`.
  - **Never between 23:00 and 01:00 UTC.**
  - Poll version.json, then start the live-check session.
- **Dates and session usage.**
  - The coordinator re-arms `send_later` check-ins; sessions sometimes go idle waiting on background e2e, so nudge them.
  - Weekly usage is at "allowed_warning", so keep parallel sessions few.
