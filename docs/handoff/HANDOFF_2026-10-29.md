## 5. Shipping checklist (what worked today)

1. **Release branch:** `release/v0.1.N` off `main`. Merge each reviewed sha (`--no-ff`; rerere on; never rebase or force-push).
2. **If the sim id changed:** bump `COOP_PROTOCOL` with a history line, add `KNOWN[N]` (compute after editing `version.js`, which is part of the sim id), remove the pending pin, and update both protocol tests.
3. **Patch note** at the top of `src/data/patchNotes.js`:
   - every line checked against the code;
   - "Co-op partners need this update too" when the protocol changes;
   - no other games' names.
4. **Independent go/no-go** (a Workflow): gates first, then e2e and a look, on the exact sha.
   - Agents must poll background runs until an `exit=` line appears, and never end their turn mid-run.
   - Known flakes: touch-drag, "mall General offer", "SSR Select Ticket".
5. **Push:** `git push origin <sha>:main`. The version is `0.1.<Pages run number>`.
   - Never ship 18:00–20:00 Central.
6. **Live check:** `scratchpad/ship-oct28/live-check.sh` with the Node relay and `NODE_EXTRA_CA_CERTS`. Never touch cert stores. In a new container, rebuild it from `docs/HANDOFF.md` §7.

## 7. How to split the next round into sessions (efficiency, less waste, same quality)

### Lessons from Oct 28–29 (what wasted usage or time)
- **Duplicate full test runs.** The coordinator ran the full vitest (about 11 min) and then the independent go/no-go ran it again on the same code. Keep only the independent run. The coordinator runs targeted tests (protocol, sim id, the files it touched).
- **Agents that ended their turn mid-run.** Go/no-go round 1 returned NO_GO only because the agent stopped while vitest ran. Every e2e and test prompt must say: background the run, write `exit=$?`, and poll until the exit line appears.
- **Workflows run only 2 agents at once on a 4-CPU container** (the cap is CPUs − 2). Batch items per agent (the art run used 8 groups of 4 girls) instead of one agent per item.
- **NovelAI makes one image at a time per account.** Parallel generators only queue. One generator per session, serialised by the lock in `nai_gen.py`.
- **The live check repeated the go/no-go's look.** After a GO, the live check only needs version.json, one smoke through the relay and the Notice. Skip its own battle look.
- **Disk is about 2 GB.** Delete `dist/`, e2e shots and the npm cache after each check, or the next build fails.
